# riff v1.0 설계 적대적 감사 결과 (2026-07-31)

- 방법: 5개 경쟁 렌즈(superpowers·OMC·harness/Agent Teams·메커니즘 신뢰성·자기 니치 속도)로 공격 → 25건 발견 → 상위 11건 적대적 재검증 (16 에이전트, 2회 워크플로)
- 판정: **real 6 / overstated 5** — real 6건은 모두 "새 스테이지·훅 없이 몇 줄 수정"으로 봉합 가능 판정

## REAL — 실질 약점 6건과 최소 보완안

### R1. 행위(유닛) 검증 부재 (vs superpowers)
PROVE Tier 0~3 어디에도 실행 가능한 행위 테스트가 없음. 타입이 맞고 빌드가 통과하는 로직 버그(경계값·조건 분기)는 medium 프로파일에서 무증상 통과.
**보완**: ① core 등급 태스크 산출물에 행위 계약 기반 실행 가능 체크 ≥1개 포함(작성 순서는 비강제) ② Tier 2 = "빌드/타입 + 누적 behavior 검증 실행" (PROVE-lite에도 포함, haiku 비용) ③ 재현 가능한 버그의 항체에는 repro 테스트 첨부 → Tier 2가 회귀 실행.

### R2. 코드 리뷰(diff 정독) 스테이지 부재 (vs superpowers)
BUILD→PROVE 사이에 코드를 "읽는" 단계가 0. 자기 리서치의 결론("최신 모델에선 brainstorm+review만 얇게 — 리뷰는 최후까지 살아남는 게이트")과 모순.
**보완**: 사이클당 1회 diff-review 서브스텝 — 단순=스킵, 보통=메인 루프 인라인 self-review, 복잡 또는 core 포함=sonnet 독립 리뷰(라우팅 표 1행 추가). Critical은 즉시 수정, Minor는 LEARN 이연. codex 있으면 codex review가 담당(폴백 매트릭스 일반화).

### R3. canvas-lint 무정의 (메커니즘 신뢰성)
핵심 셀링포인트("캔버스만으로 재시작")의 유일한 방어선이 1줄 명령 + haiku 실행 — 고무도장 위험.
**보완**: 기계적 술어로 명세: ① 헤더 Cycle N = 세션 상태 일치 ② 캔버스 [3] ↔ TaskCreate 상태 diff 청결 ③ detail/·contracts/ 링크 해소 ④ 섹션 상한 준수(위반=압축 규칙 적용 지시) ⑤ PROVE 기록 최신성.

### R4. 8신호 자가판정의 상관 맹점 (메커니즘 신뢰성)
모호한 요구를 조용히 한 가지로 해석한 모델은 "요구 모호하지 않음"에도 체크함 → FRAME 스킵 → PROVE-lite는 "잘못된 제품"을 구조적으로 감지 불가(신규 프로젝트 1사이클째가 최대 피해).
**보완**: ① FRAME 완전 스킵은 CANVAS [1]에 성공 기준이 이미 있을 때만. 없으면 스킵 대신 "가정 선언" — 채택한 해석+성공 기준 각 1줄을 [1]에 기록, STATUS에 "가정: X — 아니면 지금 말해주세요" 노출 ② depth-reproducibility 벤치마크에 정답이 '복잡'인 모호 브리프 픽스처 2~3개 추가(일관성만이 아니라 정답률 측정).

### R5. 강제 서브에이전트 라우팅의 속도 역전 (자기 니치)
순차·기계적 작업(tsc 3줄 실행, 설정 수정)까지 스폰 강제 → 사이클당 3~5회 스폰 생명주기(~2-7분 순수 오버헤드). 자기 리서치의 "인라인 전환 ~3배 빠름"(superpowers v5) 교훈과 역방향. 토큰은 줄지만 wall-clock은 늘어남 — riff의 니치는 wall-clock.
**보완**: 라우팅 조건 신설 — 스폰(모델 강제 지정)은 정당화된 경우만: 잼, 동시 실행 BUILD 태스크 ≥2, 컨텍스트 압박. 그 외 순차 태스크·PROVE Tier 0~2·LEARN 기록은 메인 루프 인라인 실행. 게이트 기준(tier 판정·항체 기록 의무)은 실행 위치와 무관하게 동일.

### R6. 계약 게이트 술어 오류 (자기 니치)
스킵 조건이 "공유 경계 없을 때"인데 웹 프로토타입은 거의 항상 API 경계가 있어 사실상 항상 발동 → 솔로 순차 빌드가 병렬용 세리머니(9항목 체크리스트, 이중 lint, 재작성 규칙)를 이유 없이 지불. 계약의 가치(컨텍스트 ~94% 압축)는 동시 에이전트 ≥2일 때만 실현됨.
**보완**: 계약 작성 조건을 "태스크 보드에 잼 또는 병렬 스폰이 계획된 경우"로 변경(BUILD-PLAN이 이미 아는 정보). 순차 빌드는 코드의 타입 선언이 계약, tsc가 lint. Tier 0 계약 검사는 contracts/에 계약이 존재할 때만 실행. deep 프로파일은 불변.

## OVERSTATED — 기각 5건 (설계가 이미 방어) + 권장 명문화 4줄

| 공격 | 기각 사유 | 명문화(선택) |
|---|---|---|
| OMC Ralph식 지속 루프 부재 | attended 루프는 의도된 트레이드오프. 에스컬레이션 사다리는 실제로 4~6회 시도 후 사용자 상담 — 원하는 동작 | PROVE 2회 실패 시 실패 유형 진단: 기계적 실패→재시도 지속, 설계 실패→SHAPE 소급 |
