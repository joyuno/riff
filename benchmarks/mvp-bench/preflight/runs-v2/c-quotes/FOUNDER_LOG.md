# FOUNDER_LOG — c-quotes

Riff가 던진 질문과 창업자(프리랜서) 답변을 순서대로 기록한다. 질문은 요약하지 않고 실제 발화 그대로 남긴다.

## 첫 요청

- 창업자 요청: 프리랜서가 견적서를 만들고 고객 진행 상태를 관리하는 앱을 만들어줘.

## Bootstrap (컴패니언 점검)

- Riff 질문: 이 프로젝트에서 riff를 처음 씁니다. ralph-loop 플러그인 / codex 플러그인 / Codex CLI / Codex 로그인 / ecc plan-canvas — 각각 설치할까요, 건너뛸까요? 없어도 riff는 기본 흐름으로 전부 동작합니다.
- 창업자 답변: 잘 모르겠어요. 가장 단순하고 안전한 방법을 추천해주세요.
- Riff 처리: 전부 Skip all로 진행(설치 없이 네이티브 폴백만 사용). `_workspace/.riff-bootstrap-skip-all` 기록.

## FRAME — Layer 1 (WHY)

- Riff 질문: 이 제품이 없으면, 그 일을 지금 어떻게 하고 있나요? 가장 최근에 그 일을 했던 때를 처음부터 끝까지 말씀해주세요. 뭘 먼저 열었고, 어디서 막혔고, 끝내는 데 얼마나 걸렸나요? 그리고 이 문제는 예전부터 있었을 텐데, 왜 하필 지금인가요? 그날 무슨 일이 있나요 — 성수기, 거래처 미팅, 계약 만료, 사람이 나감 같은 거요. 특별한 계기가 없으면 '없음'이라고 해주세요.
- 창업자 답변: 지금은 구글 스프레드시트에 고객별로 견적, 수정 범위, 발송 여부, 승인, 예상 매출을 적어서 관리해요. 새 견적을 만들 때는 시트를 열어서 이전에 비슷한 작업을 했던 고객 행을 복사한 다음에 이름이랑 금액을 손으로 고쳐서 만들어요. 그러고 나서 따로 문서로 옮겨서 이메일로 보내고, 시트에 발송했다고 표시해요. 한 건 만드는 데 20~30분 정도 걸려요. 그런데 지지난주에 복사한 행에 예전 할인 적용된 금액이 그대로 남아 있는 걸 못 보고 그대로 보냈다가, 고객이 "저번보다 싸진 거예요?"라고 물어봐서 뒤늦게 알았어요. 다행히 큰 사고는 아니었는데 식은땀 났어요. 그리고 다음 주부터 연말이라 견적 요청이 갑자기 몰리기 시작해서, 이번에 제대로 정리하고 싶어요.
- Riff 질문: 이 제품을 '고용'한 사용자가 하루가 끝날 때 '오늘 이걸 써서 다행이다'라고 느끼는 순간은 어떤 순간인가요?
- 창업자 답변: 이번 견적이 맞게 나갔는지, 어떤 고객이 아직 답장을 안 줬는지 한눈에 보여서 마음이 놓이는 순간이요. 실수로 예전 금액이나 잘못된 금액을 보낼까봐 걱정 안 해도 되는 거요.

## FRAME — Layer 2 (WHO)

- Riff 질문: 이 문제를 겪는 사람을 한 명 떠올려보세요. 그 사람이 지난주에 이 문제를 어떻게 해결했나요? 평소에 즐겨 쓰는 앱이 있다면 함께 알려주세요. 그리고 이걸 매일 누를 사람이 지금 이 대화에 계신가요? 아니라면 그 사람은 왜 쓰기 시작할까요 — 위에서 시켜서인가요, 본인이 편해져서인가요? 그리고 지금 이 일에 한 달에 얼마가 나가고 있나요 — 사람 시간이면 몇 시간 × 시급, 도구를 쓰시면 구독료, 사고가 났었다면 그때 손실액이요. 그리고 이게 작동하면 그 돈을 아끼거나 벌게 되는 사람이 누구인가요? 그 사람이 지금 이 대화에 있나요, 아니면 설득해야 하나요?
- 창업자 답변: 저요, 제가 직접 쓸 거예요. 지금은 구글 스프레드시트랑 엑셀을 같이 써요. 제가 만들고 제가 쓰는 거라 따로 설득할 사람은 없어요. 한 달에 이 일(견적 만들고 상태 챙기는 것)에 대략 10시간 정도 쓰는 것 같아요. 시급으로 치면 저는 시간당 5만원 정도로 잡으니까 한 달에 50만원 정도 되는 셈이네요. 그 돈을 아끼는 사람도 저예요.
- Riff 질문: 지금 이 일을 실제로 하는 사람이 몇 명이고, 가장 몰리는 때 하루에 몇 건을 처리하나요? 그리고 주로 어떤 기기를 쓸까요?
- 창업자 답변: 저 혼자 써요. 많을 때도 하루에 견적 3~4건 정도고, 평소엔 하루에 1건도 없을 때가 많아요. 작업은 노트북으로 다 해요, 이동 중엔 거의 안 열어봐요.

## FRAME — Layer 3 (WHAT)

- Riff 질문: 극단적으로 단순화해볼게요. 이 서비스에서 딱 하나의 화면, 하나의 버튼만 있다면 그게 뭔가요? 그 버튼을 누르면 어떤 일이 일어나나요?
- 창업자 답변: 새 견적 만들기 버튼이요. 누르면 고객 이름이랑 작업 내용, 금액 적어서 견적서 하나가 만들어지는 거요.
- Riff 질문: 거기에 2~3개를 더 추가한다면? "반드시 / 있으면 좋음 / 나중에"로 나눠주세요. 그리고 첫 버전을 언제까지 써보고 싶으신가요? (A: 2주 이내 / B: 1~2개월 / C: 3개월 이상)
- 창업자 답변: 반드시 있어야 하는 건: 고객별로 견적을 만들고 목록으로 보는 것, 각 견적이 지금 어떤 상태인지(작성중/발송함/승인됨/보류/거절 같은) 표시하는 것, 그리고 이번 달이나 이번 분기에 승인된 견적들 합쳐서 예상 매출이 얼마인지 보는 거요. 있으면 좋은 건 수정 이력 같은 거 남는 거? 나중에 해도 되는 건 딱히 지금 생각나는 게 없어요. 다음 주부터 바로 써보고 싶어서 2주 안에 됐으면 좋겠어요(A).

## FRAME — Layer 3.5 (Pre-mortem, MEASURE 앞당김)

- Riff 질문: 3개월 뒤 이게 실패했다면 이유가 뭘까요? 사업이 아니라 하루 업무가 망가지는 쪽으로도 상상해보세요. 이런 일에서는 보통 이런 게 터집니다 — 모바일에서 확인하려니 화면이 다 깨져서 오히려 더 불편해지는 경우, 그리고 예전 버전을 그대로 방치해서 나중에 어떤 게 최신인지 헷갈리는 경우요. 해당될 것 같은 게 있나요? 그리고 이 화면에 틀린 값이 그럴듯한 모습으로 떠 있으면, 누가 언제 알아챌까요? 이미 나간 건 되돌릴 수 있나요, 아니면 손으로 수습해야 하나요?
- 창업자 답변: 가장 무서운 건 제가 지난번처럼 금액을 잘못 계산해서 고객한테 보냈는데 저는 맞는 줄 알고 있다가 나중에야 아는 거예요. 한 번 나가면 이미 고객이 본 거라 어색하게 정정 메일을 다시 보내야 하니까 되돌릴 수 없다고 봐야 해요. 그리고 예전 견적이 최신인지 헷갈리는 것도 맞아요, 그것도 걱정돼요.
- Riff 질문: 그 실패를 막으려면, 출시 첫 달에 어떤 숫자를 봐야 '잘 되고 있다'고 확신할 수 있을까요? 그리고 반대로 — 얼마 동안 해보고 그 숫자가 안 나오면 접거나 방향을 바꾸실 건가요?
- 창업자 답변: 한 달 동안 계산이 틀려서 다시 보낸 적이 한 번도 없는 거, 그리고 견적 상태 보느라 엑셀을 다시 열어본 적이 없는 거면 성공인 것 같아요. 한 달 써보고도 여전히 엑셀을 같이 켜야 하면 그만 쓸 것 같아요.

## FRAME — Layer 4 (HOW, 데이터/절차/개인정보)

- Riff 질문: 이 데이터는 지금 어디에 살아 있나요? 그리고 예전 데이터를 옮겨와야 하나요, 오늘부터 새로 쌓아도 되나요? (A 엑셀·구글시트 / B 기존 시스템 / C 카톡·메일·종이 / D 머릿속 / E 아직 없음) 그리고 여기 들어가는 데이터에 사람 이름·연락처·주소·주민번호·결제정보가 있나요? 있다면 누가 볼 수 있어야 하고, 언제 지우나요? 마지막으로, 이걸 쓰기 시작해도 그대로 계속 돌아가야 하는 기존 절차가 있나요? 예를 들면 세금계산서는 여전히 홈택스로 같은 거요. 그리고 첫 한 달은 기존 방식과 같이 돌리나요, 바로 갈아타나요?
- 창업자 답변: 지금은 구글 스프레드시트에 다 있어요(A). 고객 이름, 연락처, 견적 내용, 금액, 진행 상태가 한 시트에 쭉 있어요. 예전 것도 옮기고 싶긴 한데 많지는 않아서, 처음 며칠은 최근 거래처 몇 곳만 제가 손으로 다시 입력해도 될 것 같아요. 고객 이름이랑 연락처(전화번호나 이메일)는 들어가요. 저만 보는 거라 다른 사람이 볼 일은 없고, 딱히 언제 지워야 한다는 규칙은 없는데 거래 끊긴 고객 건은 나중에 정리하고 싶긴 해요. 그리고 견적 보내는 건 지금도 이메일로 직접 보내니까 그건 계속 제 메일로 할 거예요 — 이 앱이 대신 메일을 보내는 게 아니라, 여기서 내용 만들어서 복사하거나 인쇄해서 제가 메일에 붙여넣는 식이면 돼요. 세금계산서 같은 것도 지금처럼 국세청 홈택스에서 따로 할 거고, 이 앱이 그건 안 건드려도 돼요. 처음부터 바로 이걸로 갈아타고 싶어요, 병행은 번거로울 것 같아요.

## FRAME — Layer 4 (HOW, 트레이드오프)

- Riff 질문: 실수가 문제라고 하셨죠. 두 가지 접근이 있어요: A) 실수를 아예 못하게 막는 것(입력할 때 검증, 확인 버튼 2번) B) 실수하더라도 '되돌리기'로 바로 복구하는 것. 어느 쪽이 이 상황에 더 맞나요?
- 창업자 답변: 둘 다 있으면 좋겠지만 굳이 골라야 한다면 A요 — 보내기 전에 한 번 더 확인하는 게 낫겠어요. 이미 보낸 다음에 되돌리는 것보다, 보내기 전에 막는 게 안심될 것 같아요.

## FRAME — 기술 추천 (스택)

- Riff 질문: 서버 스택은 어떻게 할까요? 로그인이 필요한가요? 데이터는 어디에 저장할까요?
- 창업자 답변: 잘 모르겠어요. 가장 단순하고 안전한 방법을 추천해주세요.
- Riff 판단/추천: 혼자만 쓰고(로그인 불필요), 노트북 한 대로만 쓰고, 서버로 옮길 데이터도 많지 않으니 정적 웹페이지 하나로 만들고 브라우저 안에 저장(로그인 없이, 인터넷 연결 없이도 그냥 파일을 열면 바로 쓸 수 있는 방식)하는 게 가장 단순하고 안전합니다. 나중에 다른 기기에서도 보고 싶어지면 그때 클라우드 저장을 추가하면 됩니다.
- 창업자 답변: 네 그게 좋을 것 같아요, 그렇게 해주세요.

## FRAME — 재질문 게이트 (근거 기반, Exa 조사 후 확인 묶음 1)

- Riff 질문: 실제 견적 도구들은 보통 작업을 여러 항목(품목·수량·단가)으로 나눠 적고 자동으로 합계를 냅니다. 항목을 여러 줄로 나눠 적을 수 있어야 하나요, 아니면 총액 하나면 이번 MVP는 충분한가요? (필요 / 이번에는 제외 / 잘 모르겠음) / 실제 견적서에서 가장 흔한 실수가 부가세(VAT) 포함·별도 표기 혼동이라고 합니다. 이 견적서에 부가세를 따로 표시해야 하나요, 아니면 필요 없나요? / 견적서에 "이 가격은 며칠까지 유효합니다" 같은 유효기간을 넣는 게 실무에서 흔한 관행입니다. 유효기간 표시가 필요한가요?
- 창업자 답변: 항목은 여러 줄로 나눠서 적고 싶어요. 작업이 여러 개로 나뉠 때가 많아서(로고 1식 + 브랜드가이드 1식처럼) 항목별로 적고 합계는 자동으로 나오면 좋겠어요(필요). 저는 간이과세자라서 부가세를 따로 안 받아요. 그냥 총금액만 보이면 될 것 같아요(제외). 유효기간은 좋은 지적이네요, 넣고 싶어요 — 예전에 몇 달 지난 가격으로 해달라고 한 적이 있어서요(필요).

## FRAME — 재질문 게이트 (근거 기반, 확인 묶음 2)

- Riff 질문: 목록에서 예전 견적을 고객 이름으로 찾아보고 싶으신가요, 아니면 최근 순서로 쭉 보이는 걸로 충분한가요? / 이미 승인되거나 거절된 견적도 나중에 수정할 수 있어야 하나요, 아니면 상태가 확정되면 내용은 그대로 두고 상태만 바꾸는 정도면 되나요?
- 창업자 답변: 최근 순서로 보이는 정도면 충분할 것 같아요, 그렇게 많지 않으니까요. 웬만하면 수정할 수 있으면 좋겠어요 — 승인된 다음에도 오타를 발견하면 고쳐야 하니까요. 그런데 고친 기록은 남았으면 좋겠어요, 나중에 뭐가 바뀌었는지 헷갈리지 않게요.

## FRAME — Layer 5 (디자인 방향)

- Riff 질문: 첫인상 느낌과 인터랙션 수준을 하나씩 골라주세요. (첫인상: A 깔끔하고 전문적 / B 감각적이고 트렌디 / C 따뜻하고 친근함 / D 강렬하고 임팩트 / E 레퍼런스 기반 추천) (인터랙션: 1 최소 / 2 부드러운 전환 / 3 풍부한 인터랙션 / 4 몰입형)

## FRAME — 최종 확인 (verdict 게이트)
