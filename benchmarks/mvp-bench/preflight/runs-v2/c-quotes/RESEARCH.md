# RESEARCH — c-quotes

Domain Research Router 2차 실행 결과. 목적은 견적서 실무에서 표준으로 취급되는
필드·계산·상태·실수 유형을 확인해 재질문 후보를 만드는 것. 검색 결과 자체는
기능이 아니라 사용자에게 확인할 질문 후보였고, 아래 각 항목은 창업자가
"필요/제외" 중 하나로 판정한 뒤에만 acceptance로 반영했다.

## 검색 근거

1. 프리랜서 견적서 작성법 — https://livesmartly.tistory.com/510
   - 공급가액/부가세/합계를 분리 표기하지 않으면 "부가세 포함인 줄 알았다"는
     분쟁이 가장 흔하다고 명시.
   - 견적 유효기간(발행일로부터 7~14일) 누락이 흔한 실수라고 명시.
2. 엑셀 견적서 가이드 — https://dxforms.com/guides/quotation-invoice-guide/
   - 표준 필드: 견적번호, 작성일, 유효기간, 공급자/수신자 정보, 품목, 수량, 단가,
     공급가액, 부가세, 합계금액.
   - 계산 표준: 금액=수량×단가, 부가세=공급가액×10%, 합계=공급가액+부가세.
3. 프리랜서 인보이스 정리법 — https://brandsee.tistory.com/77
   - 견적서(계약 전)와 인보이스(작업 후)는 별도 문서. 이번 앱은 "견적서"만 다룬다.
   - "VAT 포함/별도"를 처음부터 명시해야 분쟁이 없다고 재확인.
4. 부가세 포함/미포함 실무 가이드 — https://ttiptax.com/52
   - 금액 표시가 불분명하면 세법상 부가세 포함으로 간주됨 — 표기 방식이 실제
     세금 처리에 영향을 준다.
   - 간이과세자는 부가세를 별도로 청구하지 않고 총액 기준으로 받는 것이 일반적 —
     창업자가 "간이과세자라 부가세를 따로 안 받는다"고 답한 것과 부합.
5. AI 견적서 가이드 — https://aidocx.ai/ko/blog/ai-quotation-generator-guide-2026
   - 견적서 필수 10항목 표(발행일, 유효기간, 공급자/수신자, 품목, 수량, 단가,
     합계, 납품조건, 특기사항) 확인.
6. U+웍스 영업관리 — https://www.uplusworks.co.kr (견적 상태: 발송/승인/거절 추적)
   GTG CRM — https://gtgcrm.com/ko/features/service-selling-contracts
   (상태 흐름: DRAFT → SENT → ACCEPTED)
   - 견적 상태를 발송/승인/거절 3단계 이상으로 추적하는 것이 여러 제품에서
     공통 패턴 — 창업자가 이미 말한 "작성중/발송함/승인됨/보류/거절"과 일치.

## 근거가 바꾼 제품 결정

| 후보 | 근거 | 창업자 판정 | 반영 |
|---|---|---|---|
| 품목을 수량×단가로 여러 줄 입력 | dxforms, aidocx 표준 필드 | 필요 | A-001 (항목별 합계 자동 계산) |
| 부가세(VAT) 별도 표시 | livesmartly, ttiptax — 가장 흔한 분쟁 원인 | 제외 (간이과세자라 부가세 별도 청구 안 함) | 합계 하나만 표시, VAT 계산 로직 없음 |
| 견적 유효기간 표시 | livesmartly, dxforms, aidocx 공통 필드 | 필요 | A-006 (유효기간 입력·표시) |
| 견적 상태값 발송/승인/거절 이상 세분화 | U+웍스, GTG CRM | 이미 창업자가 5단계로 요청함(작성중/발송함/승인됨/보류/거절) | A-002 상태값 확정 |

VAT를 제외한 것은 "검색 결과가 기능을 자동 추가"한 게 아니라, 표준 관행을 근거로
질문했고 창업자가 자신의 사업자 유형(간이과세자)을 이유로 명시적으로 제외를
선택한 결과다. `_workspace/detail/knowledge-ledger.md`의 K-003을 `excluded`로
기록했다.

## 검색하지 않은 것

- 결제조건(선금/잔금), 사업자등록번호 자동 기재 같은 항목은 창업자가 요청하지
  않았고 core-closure 행(기록/상태/계산/다시찾기/다시열기/실수/전달)을 채우는 데
  필요하지도 않아 후보로 올리지 않았다. discovery-research.md 규칙대로 "요청하지
  않은 기능을 먼저 제공하지 않는다"를 따름.
- 경쟁 제품(청구스, GTG CRM 등)의 자동 이메일 발송·AI 자동화 기능은 창업자가
  Layer 4에서 "이메일은 계속 제 메일로 직접 보낸다"고 명시적으로 범위 밖
  (`must_not_break`)으로 고정했으므로 기능 후보에 넣지 않았다.
