# A — 예약·노쇼 관리

## 판정

**잠정 실패 — critical 1개, boundary 2개 미충족.** 브라우저 검증 전 결과다.

| 구분 | 결과 | 근거 |
|---|---|---|
| 예약 등록 | 통과 | 고객명·연락처·날짜·시간·시술·가격 입력과 저장 구현 |
| 겹침 차단 | 통과 | 시간 구간 충돌 검사와 사용자 메시지 구현, 단위 테스트 통과 |
| 상태 변경·기록 유지 | 통과 | 예약·완료·취소·노쇼 변경 후 저장 |
| 오늘 일정·예상 매출 | **실패** | 일정은 보이나 합계가 예정 매출이 아닌 완료 매출만 계산 |
| 새로고침 유지 | 통과(코드) | `localStorage` 저장·복원 구현 |
| 빈 고객명 | 통과 | 필수 입력 사용 |
| 과거 날짜 | **실패** | 날짜 하한 또는 제출 검증 없음 |
| 0 이하 가격 | **실패** | 0원을 허용 |
| 빈 상태 | 통과(코드) | 안내 문구 구현 |
| 390px 흐름 | 미검증 | 반응형 규칙은 있으나 브라우저 실행 미완료 |
| 조사→결정 | 통과 | 노쇼·수기 장부 근거가 예약금, 알림 확인, 충돌 차단 결정에 연결됨 |
| CANVAS 일치 | **실패** | 완료로 선언했지만 위 critical·boundary 실패가 남음 |

## 실행 증거

- `npm run build`: 통과, 충돌 검사와 완료 매출·노쇼 손실 2개 검사 통과
- 브라우저 acceptance: 실행 환경의 브라우저 연결 부재로 미검증

## 관찰

세 실행 중 요구에 가장 가까웠다. 다만 Riff의 자체 완료 선언은 독립 acceptance와
일치하지 않았다. 예상 매출의 의미와 날짜·금액 경계값을 확인하는 질문 또는 검증이
필요하다.
