# RESEARCH — c-quotes

Exa 검색 3건(예산 내 1차) + 재질문 게이트 2회. 출처는 결정을 바꿀 가능성이 가장 큰
질문(부가세 표기, 상태 수명주기, 삭제 방식) 위주로만 검색했다.

## 검색 1 — 프리랜서 견적서 필수 항목/상태 관리

- 질의: "프리랜서 견적서 필수 항목 상태 관리 방법 (발송, 승인, 수정요청)"
- 근거: https://livesmartly.tistory.com/510 (프리랜서 견적서 작성법 — 단가/부가세/유효기간 체크리스트), https://docs.channel.io/o2o_partner/ko/articles/표준견적서-작성가이드-8f4dc657 (발송 후 원본 수정 불가, 상태값 노출)
- 발견: 발송된 견적은 원본을 고치지 않고 새로 만들거나 상태만 바꾸는 게 관행. 유효기간(발행일+7~14일) 표기가 흔함.
- 제품 결정: 상태는 "발송 후에도 계속 값만 바꾸는" 단순 상태 필드로 처리(재발행 개념은 이번 범위 밖). 유효기간은 재질문에서 **제외**(사용자 판정).

## 검색 2 — 부가세(VAT) 별도 표기 관행

- 질의: "디자인 프리랜서 견적서 부가세 VAT 별도 표기 관행"
- 근거: https://ttiptax.com/52 (부가가치세법 — 표시 없으면 "부가세 포함"으로 간주), https://blog.3o3.co.kr/vat_exclusive/ (부가세 별도 표기는 관행이며 세액 구분 표기가 일반적)
- 발견: 견적서에 "포함/별도"를 명시하지 않으면 국세청 해석상 **포함**으로 간주되어 나중에 금액 분쟁의 소지가 있다. B2B는 별도, 개인 상대는 포함이 흔하다는 실무 경험담도 다수(단, 이건 SEO 목록성 개인 후기라 `industry` 신뢰도로만 반영).
- 제품 결정: 견적 금액에 "포함/별도" 토글을 넣고 자동 계산하도록 acceptance A-002로 동결(사용자 확인 완료, K-001/K-005).
- Evidence state: 표시 없으면 포함 간주 = `official`(부가가치세법 해석 기준) / 표기 관행 = `industry`.

## 검색 3 — 해외 견적 도구의 표준 필드·이력·삭제 방식

- 질의: "freelance quote/estimate tool standard fields revision history client status tracking"
- 근거: Invoice Ninja 문서(https://invoiceninja.github.io/docs/user-guide/quotes) — Draft/Sent/Approved 상태 흐름, "Sent/Draft 상태에서 삭제해도 완전히 사라지지 않고 상태만 deleted로 바뀌며 복원 가능", Billmator/Holded — 버전 이력(v1,v2,v3)으로 수정 비교.
- 발견: 업계 도구 대부분 삭제를 "완전 삭제"가 아니라 "상태 전환 + 복원 가능"으로 처리한다. 수정 이력(버전 비교)은 존재하지만 별도 기능으로 취급된다.
- 제품 결정: 삭제 대신 **보관(archive) 처리 + 복원**을 A-007로 동결(사용자 확인, K-004/K-007). 버전 이력은 재질문에서 **제외**(복잡도 증가, 사용자 판정).

## 조사가 바꾸지 않은 것

- 목록 검색/상태 필터, 새로고침 후 데이터 유지, 잘못된 값(0원 이하) 거부는 discovery-research.md의 "사용자가 말하지 않아도 기본 후보로 올리는 행" 지침에 따라 조사 없이도 기본 후보로 올렸고, 사용자가 재질문에서 "필요"로 확정했다.
- 인쇄/공유/내보내기(전달 행)는 core-closure 처분표에서 `excluded` — 실제 발송은 카톡/메일 등 외부 채널로 이미 하고 있어 이번 범위 밖.
